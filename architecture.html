Database — Schema-per-Tenant

One PostgreSQL database, multiple schemas. Each tenant gets their own isolated schema with identical table structure. The public schema holds only platform-level shared data. The schema boundary is the isolation — no tenant_id filtering needed.

Database Overview › Marketplace Publish Flow

Marketplace Publish Flow

Tenants publish products to the marketplace via a DB trigger. The marketplace only ever queries public.marketplace_listings — it never touches individual tenant schemas. Booking crosses back into the tenant schema.

sequenceDiagram participant PV as Provider participant TP as tenant_arcticfox.products participant TR as DB Trigger participant ML as public.marketplace_listings participant CU as Customer Browser participant BK as tenant_arcticfox.bookings PV->>TP: UPDATE products SET status = 'published' TP->>TR: AFTER UPDATE fires sync_to_marketplace() TR->>ML: UPSERT — title, price_from, category, location, languages Note over ML: Denormalized snapshot
No cross-schema join needed CU->>ML: GET /marketplace?location=Rovaniemi&category=snowmobile ML-->>CU: Returns matching listings (flat query, always fast) CU->>TP: GET /book/arcticfox/{product-id} Note over TP: search_path = tenant_arcticfox, public TP-->>CU: Returns departures, pricing tiers, availability CU->>BK: POST /book — guest details, departure, pricing tier BK-->>CU: Booking confirmation + booking ID

Request Lifecycle — Provider App

How a provider request flows from browser through Next.js middleware, to the Hono API, and into the correct tenant schema. The tenant schema is resolved once in middleware and passed via request context — never from user input.

sequenceDiagram participant B as Browser participant MW as Next.js Middleware participant P as Next.js Page / API Route participant A as apps/api (Hono) participant DB as Supabase B->>MW: GET /provider/products MW->>MW: Verify Supabase session cookie MW->>DB: SELECT tenant_id FROM public.users WHERE id = auth.uid() DB-->>MW: { tenant_id, schema_name: 'tenant_arcticfox' } MW->>P: Pass request + tenant context in headers P->>A: GET /api/products (with Authorization header) A->>A: Verify JWT, extract tenant slug A->>DB: SET search_path = tenant_arcticfox, public A->>DB: SELECT * FROM products ORDER BY created_at DESC DB-->>A: Product rows (no tenant_id filter needed) A-->>P: JSON response P-->>B: Rendered page Note over B,DB: Tenant schema is set once per request.

AI Feature Flows
